# 窗口场景预设

本轮开发分支：`feat/window-scenes`。首版实现和离线验证已完成，尚未发布；真实窗口与多屏效果仍待实机验收。

## 首版范围

- 在「窗口 → 场景」保存、编辑、删除命名布局；从当前可管理普通窗口中勾选，不截取屏幕内容。
- 保存应用身份、窗口匹配规则、显示器身份、相对可用区域的布局，以及可选聚焦窗口和快捷键。
- 支持用当前布局更新、另存为和重新绑定窗口。跨应用重启后按规则唯一匹配，不能把 PID 或窗口编号作为持久身份。
- 同次 Host 会话优先识别原窗口；同一应用多个候选有歧义时要求重新指定，禁止选第一个窗口代替。不同条目不能指向同一个窗口。
- 多屏按显示器 UUID 映射，分辨率和 Dock 变化使用当前可用区域计算。缺少显示器时跳过对应窗口，禁止自动挤到主屏。
- 从场景页面、菜单栏、应用内 `⌘K` 搜索或已启用的全局快捷键应用场景。
- 批量操作固定目标，逐个回读结果，分别报告已恢复、缺窗口、歧义、缺屏、尺寸约束和执行失败。未加入场景的窗口不变。
- 撤销保留本次实际移动窗口的原布局；已尝试写入但回读失败时也保留恢复点。恢复前重新核验原窗口、原显示器与可用区域，不复活已关闭窗口，不声称系统状态完整回滚。Host 重启后撤销记录失效，最多保留最近 16 个有恢复点的批次。
- 更新当前布局保留暂时缺失或无法唯一确认的旧条目与显示器，并显示保留数量；明确取消勾选已匹配窗口才移除该条目。支持显式重新映射显示器，保留窗口比例。
- 最多保存 64 个场景，每个场景最多 24 个窗口和 24 台显示器。

## 工程边界

- 主应用继续作为 SQLite 单写者，场景进入窗口设置的提交快照；Runtime Host 只执行已提交场景。
- AX 对象留在 Host；IPC 只传结构化候选、场景身份、结果和撤销令牌。协议和 JSON 备份契约按新模型升级，不保留兼容路径。
- 复用现有权限、坐标、写入/回读、快捷键和设置提交机制；新增必要的窗口枚举、匹配与批量操作，不新建常驻进程。
- 配置变更、失效请求、重复命令、窗口退出和权限撤销不能执行到另一个窗口，也不能把未知结果当成功。
- 中英文文案同步维护，功能图标使用 Lucide；布局预览使用窗口几何，无需屏幕录制权限。

## 本轮不包含

同一场景的单屏/双屏多个布局版本、显示器重连接自动恢复、启动缺失应用、打开指定文档或浏览器标签、跨 Space 迁移、退出全屏、隐藏无关应用、Spotlight/快捷指令集成。这些按此前讨论作为后续阶段。

## 验收

1. 场景新增、编辑、删除和重载，SQLite 迁移及配置导入/备份恢复遵循单一契约；无效场景不能提交。
2. 同应用多窗口的唯一匹配、歧义拒绝、重复占用拒绝，以及跨会话身份失效有必要行为回归。
3. 主副屏负坐标、比例缩放、缺屏和不可达尺寸有可检查结果。
4. 批量部分失败、重复操作、撤销、关闭窗口、配置变化和权限边界通过替身执行回归，不触碰日常桌面。
5. 窗口页面、菜单栏和搜索使用同一已提交场景；快捷键冲突/注册失败有明确反馈。
6. SwiftPM 构建、相关回归、本地化校验及完整产品编译通过。真实多屏、第三方应用和权限生命周期的桌面验收单独记录，离线通过不能替代实机结论。
