# 目录结构与职责

按当前源码与 SwiftPM / XcodeGen 声明整理。目录按职责聚合，编译模块按进程边界隔离；二者不是一一对应。依赖关系见[架构](架构.md)，构建命令见[开发](开发.md)。

## 归属规则

- 新功能进入 `Features/<功能>`。只有涉及独立进程或编译隔离时才分 Domain、Runtime、Client；壁纸和外观按自身职责组织，不强制套四层目录。
- Finder、Window、Mouse 的 `Domain` 分别编译为领域库，`Runtime` 编译为后台库，Finder `Extension` 独立编译。`Settings` 与 `Client` 同其余前端功能一起编译到 `ArcKitApplication`，目录聚合不扩大进程的链接范围。
- `Application/Composition/ApplicationWorkspace.swift` 组装各页面；Shell 接收页面内容，不逐层传递所有功能服务。功能搜索项与标题/图标由各功能声明，应用决定侧栏顺序和统一搜索行为。
- 功能设置只持有 `SettingsEditor<本功能配置>`，不持有整份 `SettingsModel`。模板库和跨功能动作单独注入，继续使用同一个草稿、撤销历史和提交门禁。
- 壁纸、背景和图源存储必须显式接收数据库，不能自行选择生产路径或调用应用数据库工厂。表映射随功能维护，连接、迁移执行顺序和备份由应用统筹。
- 壁纸通过 URL、素材类型和异步动作交付背景；两个功能不直接引用对方模型。跨功能连接位于 Composition。
- `Platform/Persistence` 保留为独立编译模块。轻量记录布局契约仍在 Platform，Finder 扩展不会因配置定义而链接 GRDB。
- `UI` 不放 Finder 模型扩展、具体功能服务或全局配置。业务图标放回功能设置目录，泛型编辑绑定不保存第二份草稿。
- Catalog 按**编译 Bundle**归属，不按每个源码子目录复制。前端功能共用 Application Bundle 的原生 internal 符号；生成代码只进入构建目录。
- `.build` 和 `dist` 不代表当前安装状态。生产数据使用 `~/.arc-kit/`，详见[架构](架构.md)。
