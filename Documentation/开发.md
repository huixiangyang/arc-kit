# 开发与验证

本文面向源码贡献者。模块职责见[架构](架构.md)，协作方式见[贡献指南](../CONTRIBUTING.md)，安装与签名见[交付](交付.md)。

## 工具与构建入口

开发需要完整 Xcode 26+、随附 Swift 工具链、XcodeGen 和 Python 3；本地化使用 Apple `xcstringstool`。产品最低 macOS 13，Xcode 的 Swift Testing target 最低 macOS 14。SwiftPM 与 XcodeGen 固定 GRDB 7.11.1，使用系统 SQLite。

维护 [Package.swift](../Package.swift)、[project.yml](../project.yml) 和 [Build/Xcode](../Build/Xcode/)；生成的 `.build/xcode/ArcKit.xcodeproj` 不是配置来源。SwiftPM 用于开发与模块回归，完整安装包必须由 Xcode 构建，包含主应用、Host 和 Finder 扩展。

新增功能先确定进程归属：领域、后台与扩展分别编译，前端设置与客户端聚合在功能目录并归 `ArcKitApplication`。前端 String Catalog 保留在 Application 的资源目录；不要为物理目录重排复制 Catalog 或修改 Apple 生成符号的可见性。功能通过专用配置编辑接口和注入的存储/动作接入，不读取全局配置单例，也不自行创建生产数据库。功能入口、搜索词归功能；应用组合层负责导航顺序、页面组装和跨功能连接。

Application 显式链接 AVKit。仅依赖 SwiftUI `VideoPlayer` 的自动链接可能缺少 `AVPlayerView` 基类；播放器改动还要覆盖实际实例化，不能只验证编译。

### 管理页面调试

在仓库根目录执行：

```sh
swift build --product ArcKitApp
.build/debug/ArcKitApp --ui-debug
```

[.vscode/launch.json](../.vscode/launch.json) 只保留 `Debug ArcKit Settings`，使用相同 `--ui-debug` 入口。[项目设置](../.vscode/settings.json) 关闭 Swift 扩展自动生成启动项，避免重新添加不带调试隔离的 App 或独立 Host 入口。

窗口为 `Arc Kit · Debug`，复用真实页面和配置绑定。数据独立保存到 `.build/ui-debug/data/`，首次使用默认配置，不导入生产数据、不注册 Host 或登录项。关闭窗口或 `⌘Q` 退出；修改代码后增量编译再运行，不升构建号、不替换安装版。

Debug 支持素材导入、在线检索、预览和调试窗口背景，不更换真实桌面或自动轮换。备份恢复等待配置与媒体写入完成，恢复后重新加载模型，不启动后台。权限及后台检查显示调试边界，不能用来验收 Finder、鼠标、窗口或系统壁纸执行。

`--ui-debug` 只在 Debug 编译中存在。不带此参数直接运行主程序会进入产品生命周期。AppKit 必须由同步 `main` 进入事件循环；不能在 `async main` 的 MainActor 任务中调用 `NSApplication.run()`。入口变更需在授权的安装验收中检查启动、退出和重启。

### 完整产品编译

```sh
mkdir -p .build/xcode
xcodegen generate --project .build/xcode
xcodebuild -quiet -project .build/xcode/ArcKit.xcodeproj -scheme ArcKit \
  -configuration Release -destination 'generic/platform=macOS' \
  -derivedDataPath .build/derived-data \
  CODE_SIGNING_ALLOWED=NO build
```

该命令只验证完整产品编译，不安装、打开应用或注册后台，也不提供可分发签名。不要在仅文档或轻微样式调整时自动打包安装。

工程固定生成到 `.build/xcode`；`ARCKIT_SOURCE_ROOT` 指向仓库根，产品声明和嵌入脚本以它解析源码路径。模板、Brand、Aura、Licenses 使用带父组的整目录资源引用，避免 XcodeGen 的 `folder` 类型将路径错误解析到生成工程目录；仓库根的 Licenses 显式配置 Resources 父组。调整资源声明后须检查完整包内的实际文件。

更新使用 Sparkle 官方实现；发行时用官方工具验证订阅与安装包签名，并检查源码版本、构建号及 SHA-256 一致。完整安装与重启仍须实机验收，不能用签名验证代替。

## 按变更选择验证

不为布局、文案、目录移动编写源码字符串或常量镜像测试。优先运行相关的现有行为回归；跨模块行为变更和 CI 才执行全套。纯文档变更检查事实、路径、链接及差异即可。

```sh
# 配置提交与失败恢复
swift test --filter 'SettingsCommitTests|CommittedSettingsTests'

# 鼠标路由、平滑与取消
swift test --filter MouseScrollPipelineTests

# 素材、来源、桌面事务与备份
swift test --filter WallpaperTests

# 跨模块离线回归或无活动显示器的 CI
swift test --skip 'MouseScrollPipelineTests/(appKitConsumption|displayLinkRecovery)'

# 在有活动显示器的开发机验证 AppKit 消费与真实帧刷新
swift test --filter 'MouseScrollPipelineTests/(appKitConsumption|displayLinkRecovery)'
```

测试集中在 [Tests/ArcKitTests](../Tests/ArcKitTests/)，一个 target；辅助对象放在使用它的测试文件内，不恢复独立 Runner 或通用 Support 层。

| 测试 | 关键回归范围 |
| --- | --- |
| InputEventLoopTests | RunLoop 同步交接、闭包释放与析构崩溃 |
| WindowLayoutTests | 多屏坐标、台前调度比例、捕获令牌、目标失效与非激活面板 |
| MouseScrollPipelineTests | 方向、窗口标注、AppKit 消费、投递取消、会话隔离、帧刷新器失败恢复 |
| RuntimeHostTests | 注册、有限重连、迟到回包、退出确认、分主体权限、等待批准与 Finder 按需休眠 |
| CommittedSettingsTests | 失败草稿不发布、数据操作互斥、设置导入撤销及失败恢复点保护 |
| SettingsCommitTests | SQLite 事务、磁盘写满、独立读取、单写者、坏库保护、备份恢复与通信顺序 |
| LocalizationTests | 原生语言资源、复数与参数重排、语言事务与迁移、Finder/Worker 传递 |
| WallpaperTests | 离线迁移、跨根恢复、素材修复、来源校验、分页与下载取消、桌面回读和回滚、背景保存、柔光配方与自动规则 |
| FinderTests | 文件回滚、防重放、Worker 回收、图标编码、终端入口、菜单目标关联与打开回执 |

验证边界：

- AppKit 滚动消费与 CVDisplayLink 恢复需要活动显示器，CI 明确排除这两类；前者使用隐藏窗口，不发送系统输入。通过不代表真实 USB 鼠标到目标应用的路由成功。
- 权限与后台用注入的回包、系统状态和传输验证；不请求真实 TCC、不启用扩展、不启动终端。不把测试进程授权冒充产品授权。
- 壁纸使用临时素材及替身桌面，不修改真实壁纸。文件任务内回滚不能证明强杀或断电后的恢复；iCloud 观察范围测试不能证明系统会回调。
- 更新回归使用离线 HTTP 替身，不下载或打开安装包；官网正式清单、公证包和真实升级须另行验收。
- 真实安装验收单独记录版本、设备、触发操作和结果，不沿用历史通过记录。
- 非本地化测试用错误类型、功能标识或当前语言的资源比较结果，不用固定中文片段判断成功；GitHub macOS Runner 默认英文。中英文译文原文与格式化的断言集中在 `LocalizationTests`，显式指定语言。

## 本地化与资源

Finder 的三个空白 Office 模板由 `Build/Scripts/generate-office-templates.py` 从最小 OOXML 定义生成，只依赖 Python 标准库。修改结构后运行该脚本并提交生成文件；运行 `python3 Build/Scripts/generate-office-templates.py --check` 可验证逐字节重现，Quality CI 也执行此检查。生成结果已分别用 DOCX、XLSX、PPTX 解析器读取验证；这不替代不同版本 Office 的实际打开验收。其他文件模板的归属记录见 [Licenses](../Licenses/README.md)。

译文在各模块的 `Resources/Localization/*.xcstrings` 中维护，源语言 English，目前支持 en 与 zh-Hans。Catalog 文件名就是查找表名；模块内按功能拆表，不建立总词库或公开的词条转发层。

| 所属模块 | 资源职责 |
| --- | --- |
| Platform | `Platform` 基础设施文案；`Common` 通用按钮及系统语言名称 |
| Persistence、Finder、Window、Mouse | 各自的领域、校验和错误文案 |
| Finder/Runtime、Finder/Extension、Window/Runtime、Mouse/Runtime | 后台执行及扩展交互文案 |
| Application | 按独立功能维护：设置及壁纸见下表；其他为 `App`、`FinderSettings`、`WindowSettings`、`MouseSettings`、`Overview`、`Runtime`、`Diagnostics`、`Updates` |
| App / Host 入口 | `AppEntry` / `HostEntry`；共用 [InfoPlist.xcstrings](../Targets/ArcKitApp/Resources/Localization/InfoPlist.xcstrings) 的系统授权用途说明 |

设置及壁纸的词表归属如下；同一词表内包含所有支持语言，不创建 `en.xcstrings` / `zh.xcstrings`。文件名是词表名，语言由条目内部的 `localizations` 指定。

| Catalog | 负责的文案 |
| --- | --- |
| [Settings](../Sources/Application/Resources/Localization/Settings.xcstrings) | 通用偏好、语言、配置校验与保存状态 |
| [AppBackground](../Sources/Application/Resources/Localization/AppBackground.xcstrings) | 应用背景编辑、存储与应用结果 |
| [DataManagement](../Sources/Application/Resources/Localization/DataManagement.xcstrings) | 存储管理、备份恢复、旧数据导入与卸载入口 |
| [About](../Sources/Application/Resources/Localization/About.xcstrings) | 关于页及版本更新界面 |
| [Wallpaper](../Sources/Application/Resources/Localization/Wallpaper.xcstrings) | 图库、导入、收藏及壁纸页面导航 |
| [WallpaperSources](../Sources/Application/Resources/Localization/WallpaperSources.xcstrings) | 在线图库、动态渠道、订阅与混合浏览 |
| [WallpaperPlayback](../Sources/Application/Resources/Localization/WallpaperPlayback.xcstrings) | 屏幕选择、壁纸应用、回滚、轮换与播放设置 |
| [WallpaperMedia](../Sources/Application/Resources/Localization/WallpaperMedia.xcstrings) | 下载、媒体校验、清晰度、预览与循环编辑 |

新增文案按功能含义选择词表；例如 WallpaperModel 编排多个功能，背景结果仍归 AppBackground，屏幕应用结果归 WallpaperPlayback。拆表以功能维护边界为准，不按 JSON 行数或每个 Swift 文件拆分；迁移时同步修改调用，不保留旧表中的同义副本。跨表迁移仍保留 key、译文、参数和复数结构。

[Common.xcstrings](../Sources/Platform/Resources/Localization/Common.xcstrings) 只维护一份，通过 target 资源声明编入各模块。这样通用文案和业务文案都可使用当前模块的原生 internal 访问器，不跨模块导出资源符号；领域含义不同的同名文案分别维护。

在 Xcode String Catalog 编辑器维护简短、稳定的语义 key、译文和上下文注释，例如 WallpaperPlayback 表的 `apply.restoreUnconfirmed`。新增条目设置为手动管理，数量使用 Vary by Plural，参数保留原生位置及类型。不以类名加完整句子、中文句子、哈希或下标作为新 key；不拼接完整句子，不翻译用户输入、路径、来源标题或持久化 ID。

```swift
L10n.string(.Common.cancel)
L10n.string(.Wallpaper.libraryCount(count))
L10n.string(.WallpaperPlayback.applyRestoreUnconfirmed(displayName))
```

Xcode 通过 `STRING_CATALOG_GENERATE_SYMBOLS=YES` 原生生成访问器并编译 Catalog；SwiftPM 的 [CompileStringCatalog](../Build/Plugins/CompileStringCatalog/plugin.swift) 调用 Apple `xcstringstool`，生成当前 target 的访问器和 Bundle 资源。生成代码保持工具默认访问级别，全部留在构建目录，不入库、不修改生成结果。SwiftPM manifest 使用 tools 6.1；开发仍需 Xcode 26+。

编辑器通过 [.sourcekit-lsp/config.json](../.sourcekit-lsp/config.json) 和 [VS Code 项目设置](../.vscode/settings.json) 关闭 SourceKit-LSP 自动后台索引，读取普通构建目录 `.build/`，并沿用 `Package.resolved` 锁定的依赖。首次打开项目或修改跨模块接口后执行 `swift build` 更新模块与索引；补全、诊断和跳转仍由语言服务提供，但跨文件索引不会自行后台重建。修改此配置后，需要在编辑器中重启 Swift 语言服务才会生效。

`GeneratedStringSymbols_<表名>.swift` 是按 target 生成的本地化访问器，同名表在不同模块分别生成属于正常行为。当前工具链的自动后台索引会遗漏插件源码输出映射，导致 `.d`、`.dia`、`.swiftdeps` 或 `.swiftmodule` 落到根目录；独立缓存和正常构建准备模式均未解决重复索引时的问题，因此暂用上述手动构建索引方式。清理只针对根目录内确认过的编译副产物，忽略规则用于防止残留误入库；不要删除 Catalog、关闭符号生成或手改生成的输出映射。旧 `.build/sourcekit-lsp/` 是可重建缓存，须在旧语言服务停止后才能清理。工具链升级后需验证连续两轮索引及输出位置，再考虑恢复后台索引。

SwiftPM 按目录复制语言资源，插件必须每个 target 一次输出完整的 `lproj`，不能逐表输出多个同名语言目录。[编译脚本](../Build/Scripts/compile-string-catalog.sh) 每次清空该插件的资源输出，避免已删除语言或复数表残留。Host 每次构建重新嵌入 Framework；资源调整后核对 App、Host、扩展实际包内内容。

```sh
# 修改 Catalog 后直接构建，无需手动生成或提交 Swift 访问器
python3 Build/Scripts/localization.py
swift test --filter LocalizationTests
```

[localization.py](../Build/Scripts/localization.py) 自动发现 Catalog，从 `project.yml` 的 `developmentLanguage` / `knownRegions` 获取语言声明，检查完整译文、上下文、SwiftPM 源语言和产品语言声明，并调用 Apple 编译器校验。增加语言时更新工程 `knownRegions`、产品 `CFBundleLocalizations`、各 Catalog 译文及 `ArcKitLanguage` 选择和系统语言匹配；校验脚本无需增加语言分支。

`L10n` 只负责当前语言上下文，资源查找、插值、复数和格式化交给 Foundation。公共方法的默认文案在方法体内解析，不将内部资源符号暴露到公共默认参数中。翻译交接使用 Xcode Export/Import Localizations；无需另建 JSON 翻译副本。

功能图标使用 Platform 中的 Lucide；软件和文档类型图标按系统来源获取。第三方归属只维护 [Licenses](../Licenses/README.md)，通过 Xcode 将该目录整体复制到主应用，不复制多份许可证到各 target。

品牌正式导出位于 `Targets/ArcKitApp/Resources/Brand/`，不直接作为运行资源整目录复制。运行时标记位于 `Sources/Application/Resources/Brand/`，应用图标位于 `Assets.xcassets/AppIcon.appiconset`。变更品牌需同步深浅 PNG、ICNS 和标准图标槽位，核对透明边缘、单色辨识与资源打包；生成原图和提示词存仓库外。品牌标记独立于 Lucide 功能图标。

菜单栏品牌图标由 `Sources/UI/ArcBrandMark.swift` 中的 `ArcBrandImage.menuBar` 加载现有 Logo，使用 18pt 模板图，由 AppKit 处理深浅背景与选中态；异常提示使用 Lucide。轻微样式修改先做离屏预览，不自动替换安装版或操作桌面。

## 代码边界

- Application、Features、Platform、UI 四个源码入口按职责组织；独立进程或编译隔离才增加 target。每份 Swift 源码只属于一个 target，同 target 文件名唯一；不设 Shared、Common、万能 Models 或纯转发层。
- SwiftPM 的 Application 排除 Platform、各功能 Domain、Runtime、Extension 目录，Platform 排除 Persistence；Catalog 交给插件，Xcode 单独声明资源。除此以外不以任意 exclude 或源码白名单隐藏文件。模块改动同步依赖、import、Framework 嵌入及资源声明。
- 主应用单写设置；后台只消费已提交快照。SettingsModel 管草稿与提交，RuntimeSettingsSession 发布提交事件；View 不注册服务、不建立第二份运行配置。
- 菜单栏可见性只由已提交的 `showMenuBarIcon` 控制；隐藏时结束菜单捕获和该入口的点击监听，不改变 Host 或功能开关。旧 SQLite 由 `menu-bar-visibility-v1` 一次性补字段，配置 JSON 契约升为 22，旧版本 JSON 备份按既有规则拒绝；完整数据库备份通过迁移恢复。两个图标均隐藏时，LaunchServices 的 open/reopen 仍须打开设置窗口。
- UU 远程旁路是可编辑的普通 `MouseAppScrollProfile`，默认行为为 `system`；`mouse-uu-remote-rule-v1` 只为旧库补一次缺失规则并推进 runtime revision，已有同 Bundle ID 规则不覆盖。解码与运行时不注入默认规则，删除后重启、新版备份恢复和后续升级不得补回。
- 鼠标应用页先展示“未单独设置的应用”，再展示每个应用的单独设置。前者映射 `scrollScope` 的回退行为，后者直接编辑 `behavior`；应用规则始终优先，不新增配置副本。应用选择器与名称同行，自定义参数仅在对应行内显示；快捷添加使用按钮显示的应用身份，不在点击时重新捕获目标。
- 鼠标规则 `note` 为可留空的持久化文本，JSON 契约现为 23，旧版本 JSON 按既有规则拒绝，完整数据库备份经迁移恢复。`mouse-rule-note-v1` 补说明列，仅为仍采用 `system` 行为的原始 UU 预置规则填用途，已有自定义规则留空；清空或删除后不补回。更早的 UU 迁移只写当时的列，不能提前解码依赖新字段的完整配置。说明编辑只推进 data revision；数据库提交通过 `hasSameRuntimeConfiguration` 排除说明；Host 协调器以已提交 `runtime_revision` 为唯一依据，避免重复字段比较漏掉语言等变化。
- ApplicationRuntime 显式持有协调器和客户端；注册与系统状态归 RuntimeHostSystem，控制连接归 RuntimeHostTransport。不恢复静态可变协调器或客户端反向查询全局实例。
- Finder Dispatcher 穷尽分发 payload。文件执行复用计划、同卷暂存、排他发布与回滚；固定工具传 argv，脚本入口才处理脚本。退出码不代替文件结果核对，未知结果不自动重放。
- Application/Storage 拥有业务迁移、备份恢复和维护。DataTransferCoordinator 管交互，DataManagementModel 管任务与结果，SettingsModel 只管配置编辑与提交；各入口共用 SettingsOperationGate 租约，不新增独立 busy 开关。SupportDiagnosticsCoordinator 管诊断导出，AppController 连接生命周期钩子。
- Persistence 不出现具体业务表的修复规则；ApplicationStorageMigrations 注入有序迁移与外键、索引。移动迁移不改标识和顺序，语言迁移同样必须保留。Host 只读构造不注入迁移。
- 登录启动服务归 Lifecycle；隐藏文件和截图位置归 Features/SystemTools。运行态窗口诊断归 Diagnostics，不因名称含 SmokeTest 删除或挪到单元测试。
- 页面局部状态由实际子 View 持有，跨组件通过明确绑定传递；不以跨文件 extension 拼共享页面状态。新功能放所属目录，删除废弃 API 和旧入口。
- 输入线程交接必须使用可逃逸闭包，唤醒前释放业务闭包；不恢复 `withoutActuallyEscaping` 包装。普通状态查询不重建连接；鼠标保留带窗口标注的入口与 PID 路由。
- 必要注释使用中文。授权能力变更同步 `Build/Xcode/Products.yml`、entitlements 与权限文档；未签名编译不能证明真实 TCC 行为。

## 文档维护

文档随同一功能改动更新；只修改版本号或追加“已完成”不能替代更新现有说明。每次收尾按下表检查，删掉已失效的入口、路径和结论。

| 发生的变更 | 同步位置 |
| --- | --- |
| 功能入口、默认行为、权限、配置或恢复流程 | 使用；影响整体入口时同时更新 README |
| 模块、进程、数据格式、运行链路 | 架构；目录或资源归属变化同步[目录结构](目录结构.md)，命令变化同步开发 |
| 构建工具、依赖、验证方式、资源生成 | 开发；新增第三方内容同步 Licenses |
| 构建、安装、回退或发布 | 交付维护流程；版本说明记录变化与限制；私人安装证据保留在本地 |
| 未完成实现或真实验收 | 规划只保留缺口、优先级与完成条件；完成后移入版本说明或交付 |

交付文档描述发布与升级流程，规划保留待办；README 面向使用者与贡献者。个人设备、临时 PID、完整日志和安装证据存本地 `.build/` 或数据根的诊断目录，不进入公开文档。版本相同但源码改变时，明确“待交付”，不能覆盖旧包事实。下一次打包应分配新的构建号。

[CI](../.github/workflows/quality.yml) 在 Xcode 26 下依次校验本地化、运行离线回归、编译双架构 Release 并上传测试 DMG / ZIP。[Release](../.github/workflows/release.yml) 由版本 Tag 触发，复用同一构建，再签名、公证和发布。两者共用 [package-app.sh](../Build/Scripts/package-app.sh) 校验完整产品、签署嵌套组件与归档；该脚本不安装或启动程序，配置见[交付](交付.md#github-actions-安装包)。仓库只维护这些必需构建工具，不恢复通用 Tooling 或安装、图标生成脚本集合。`.build/`、`dist/` 均为生成物，不据此自动认定当前源码已安装或发布。

## 生成物位置

XcodeGen 工程固定输出到 `.build/xcode/`，DerivedData 通过命令显式指向 `.build/`；CI 使用同样的路径约定。String Catalog 的 Swift 访问器与语言资源由插件生成到 `.build/plugins/`。不要把 `.swiftmodule`、`.swiftdeps`、`.dia`、依赖文件或生成的 Swift 源码放到仓库根目录。

当前编辑器配置关闭后台自动索引，使用正常构建的索引结果。工具链更新后，先检查根目录是否泄漏编译产物、资源符号与跨模块跳转是否正常，再恢复自动索引。
